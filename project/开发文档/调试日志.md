# 调试日志设计

## 1. 目的

调试日志用于排查 GUI 交互、程序接口和内部状态问题，默认关闭，不影响正常运行。

当前重点用于定位键盘、鼠标和滚轮事件是否进入 Qt，以及事件进入后程序接口和状态是否发生预期变化。

## 2. 日志位置

日志位于工作目录下的 `logs/`，与 `settings.json` 使用同一目录基准：

- 开发运行：`project/logs/`
- 打包运行：EXE 所在目录的 `logs/`

每次启动创建独立的 JSON Lines 文件：

```text
logs/debug_YYYYMMDD_HHMMSS_microseconds.jsonl
```

`logs/` 不提交 Git。工作目录中的本地测试 `*.png` 也不提交 Git。

## 3. 命令行参数

### `--log`

日志总开关。

如果只指定 `--log`，则记录 `events`、`api`、`state` 三类普通日志；鼠标移动必须额外指定 `--log-mouse-move`。

### `--log-events`

记录程序收到的键盘、鼠标按键和滚轮事件，包括：

- 事件目标控件类型
- 键盘按键和修饰键
- 鼠标按键、按钮状态和位置
- 滚轮角度增量和像素增量

高频 `MouseMove` 不属于该参数的普通事件记录。

该类别用于判断操作是否实际进入 Qt 事件系统。

### `--log-api`

记录主要程序接口调用，包括开始、结束、成功、失败和关键参数。

当前覆盖窗口中的打开图片、适应窗口、原始尺寸、遮罩设置、区域切换、快捷键刷新、导出，以及画布缩放等关键接口。

### `--log-state`

记录关键操作后的内部状态快照，包括：

- 当前图片路径和尺寸
- 当前缩放比例
- 当前选中区域
- 当前选中分割线
- 分割线坐标
- 区域保留/删除状态
- 遮罩透明度

### `--log-mouse-move`

独立控制鼠标移动日志，默认关闭。

启用后不会逐条保存 `MouseMove`。日志器会将连续且以下状态均未变化的一段移动合并为一条 `mouse_move_segment`：

- 目标控件
- 鼠标按钮状态
- 修饰键状态

每段只保存开始/结束时间、持续时间、开始/结束位置、按钮状态、修饰键状态以及原始事件数量。

当按钮、修饰键或目标控件发生变化，或者出现键盘、鼠标按键、滚轮等其他事件时，当前移动段立即刷新并开始新的状态段；程序退出时也会刷新最后一段。

因此，即使鼠标移动事件达到每秒数百次，也不会生成数百条逐点日志。

## 4. 参数组合规则

```text
python main.py --log
```

记录 `events`、`api`、`state` 三类普通日志，不记录鼠标移动。

```text
python main.py --log --log-events
```

只记录键盘、鼠标按键和滚轮事件。

```text
python main.py --log --log-events --log-api --log-state --log-mouse-move
```

记录全部普通日志，并额外记录合并后的鼠标移动段。

分类参数没有 `--log` 总开关时不会启动日志。

## 5. 启动时快捷键快照

日志创建后、主窗口创建前，会读取当前配置中的完整快捷键配置，并写入：

```text
category: state
name: startup_shortcuts
```

该快照包含本次程序启动时全部快捷键字段和值。因此后续即使用户在程序运行期间修改快捷键，分析日志时仍能知道本次运行开始时使用的快捷键配置。

快捷键修改后，`edit_shortcuts.saved` 和 `refresh_shortcuts.*` API 日志还会记录新的配置以及重新注册结果。分析事件时，应以事件发生前最近一次已记录的快捷键配置为准；`startup_shortcuts` 是本次运行的初始基准。

## 6. 日志记录原则

日志功能不能改变正常业务逻辑。日志写入失败时不得阻止主程序运行。

键鼠事件通过 `QApplication` 的全局事件过滤器记录，因此可以观察事件实际到达的 Qt 控件，而不仅仅记录业务层已经处理的事件。

鼠标移动属于高频数据，默认关闭；即使开启，也使用状态分段而不是逐事件记录，以控制日志体积。

## 7. 滚轮问题排查方法

针对 `Alt + 鼠标滚轮` 无响应的问题，建议使用：

```text
python main.py --log --log-events --log-api --log-state
```

然后分别执行：

1. 普通滚轮一次；
2. 按住 `Alt` 滚轮一次；
3. 再执行“原始尺寸”；
4. 再执行“适应窗口”。

重点检查日志中的 `wheel`、画布滚轮处理、缩放接口和 state 中的 `zoom` 变化。

如果还需要确认鼠标在事件发生前后的具体位置，再增加 `--log-mouse-move`。

判断逻辑：

```text
没有 wheel 事件
    ↓
Qt 没有收到滚轮事件，继续排查事件传播/系统层

有 wheel，但没有 Alt
    ↓
继续排查修饰键状态

有 Alt + wheel，但没有 zoom
    ↓
继续排查滚轮增量或缩放条件

有 zoom / set_zoom
    ↓
继续排查缩放后的绘制、滚动范围和视觉结果
```
