# 调试日志设计

## 1. 文档定位

本文档属于**实现细节说明**，记录当前版本调试日志系统实际采用的记录范围、分类、字段和启用方式。

日志系统实现发生变化时，应及时更新本文档；日志需求或排查目标发生变化时，再相应调整日志设计。

调试日志用于排查 GUI 交互、程序接口和内部状态问题，默认关闭，不影响正常运行。

当前重点用于定位键盘、鼠标和滚轮事件是否进入 Qt，以及事件进入后程序接口和状态是否发生预期变化。

## 2. 日志位置

日志位于工作目录下的 `logs/`，与 `settings.json` 使用同一目录基准：

- 开发运行：`project/logs/`
- 打包运行：EXE 所在目录的 `logs/`

每次启动创建独立的 JSON Lines 文件：

```text
logs/debug_YYYYMMDD_HHMMSS_microseconds.jsonl
```

`logs/` 不提交 Git。工作目录中的本地测试 `*.png` 也不提交 Git。

## 3. 日志的通用信息

无论具体日志属于哪一种业务分类，每条日志记录都包含以下基础字段：

| 字段 | 含义 |
| --- | --- |
| `time` | 日历时间，精确到毫秒 |
| `monotonic` | 单调时钟值，用于分析事件先后和时间间隔 |
| `category` | 日志分类，例如 `api`、`state`、`events`、`interaction` |
| `name` | 具体日志事件名称 |
| `data` | 该事件附加的数据；没有附加数据时省略 |

一次程序运行开始时，还会记录一组**运行上下文信息**，用于知道这次日志是在什么启动条件下产生的：

- 进程 ID（`pid`）。
- Python 版本（`python`）。
- 本次启用的日志分类（`categories`）。
- 程序完整命令行参数（`argv`）。
- 启动时快捷键配置快照。

其中命令行参数记录的是程序实际收到的 `sys.argv`，因此分析日志时可以直接知道本次运行是否使用了 `--log-events`、`--log-interaction`、`--log-mouse-move` 等调试选项，而不需要回忆启动命令。

## 4. 日志分类

当前日志系统实际使用以下分类：

### `app`

记录日志系统和程序生命周期相关信息，包括：

- `logger_started`：日志文件创建并开始记录时产生，包含 PID、Python 版本和启用分类。
- `logger_stopped`：日志系统关闭时产生。
- `uncaught_exception`：未捕获异常，包括异常类型和异常消息。

### `config`

记录配置相关的调试快照。目前包括：

- `startup_shortcuts`：程序启动时的完整快捷键配置。

### `api`

记录程序入口和关键程序接口调用。目前入口层明确记录：

- `application_start`：程序启动，包含完整命令行参数 `argv`。
- `application_exit`：程序退出，包含退出码 `exit_code`。

后续增加业务 API 日志时，应在这里同步记录实际覆盖范围，不应仅根据计划功能描述“已经覆盖”。

### `state`

记录关键操作后的内部状态快照，目前主要包括：

- 当前图片路径和尺寸。
- 当前缩放比例。
- 当前选中分割线。
- 当前分割线坐标。
- 当前区域及其保留/删除状态。
- 删除区域集合。
- 遮罩透明度。
- 画布设置、绘制和文档切换等诊断状态。

### `events`

记录 `QApplication` 实际收到的键盘、鼠标按键和滚轮事件，包括：

- 事件目标控件类型。
- Qt 事件类型。
- 键盘按键、修饰键、文本和自动重复状态。
- 鼠标按键、按钮状态、修饰键和位置。
- 滚轮位置、角度增量和像素增量。

高频 `MouseMove` 不属于该分类的普通逐事件记录。

该类别用于判断操作是否实际进入 Qt 事件系统。

### `interaction`

记录画布内部交互处理链，包括：

- 画布收到的鼠标按下、移动、释放。
- 平移开始、移动和结束。
- 平移前后的滚动条位置。
- 交互时的按钮状态、鼠标位置和缩放比例。

该分类关注的是**程序内部如何处理事件**，与 `events` 关注“Qt 是否收到事件”相区分。

### `mouse_move`

该分类由 `--log-mouse-move` 单独控制，记录鼠标移动轨迹的分段摘要。

连续且以下状态均未变化的一段移动合并为一条 `mouse_move_segment`：

- 目标控件。
- 鼠标按钮状态。
- 修饰键状态。

每段保存：

- 开始/结束时间。
- 持续时间。
- 开始/结束位置。
- 按钮状态。
- 修饰键状态。
- 原始移动事件数量。

当按钮、修饰键或目标控件发生变化，或者出现键盘、鼠标按键、滚轮等其他事件时，当前移动段立即刷新并开始新的状态段；程序退出时也会刷新最后一段。

因此，即使鼠标移动事件达到每秒数百次，也不会生成数百条逐点日志。

## 5. 命令行参数

### `--log`

日志总开关。

指定后启用推荐的默认日志配置：`api`、`state`，以及程序生命周期和配置快照等基础日志。默认不启用高频 GUI 事件和鼠标移动日志。

### `--log-events`

在 `--log` 基础上追加 `events` 日志，记录 QApplication 收到的键盘、鼠标按键和滚轮事件。

### `--log-interaction`

在 `--log` 基础上追加 `interaction` 日志，记录画布内部交互处理链。

### `--log-mouse-move`

在 `--log` 基础上追加合并后的 `mouse_move_segment` 日志。

这些细化参数本身不能单独启动日志；没有 `--log` 总开关时不会创建日志文件。

## 6. 常用启动方式

```text
python main.py --log
```

记录推荐的默认日志。

```text
python main.py --log --log-events
```

在默认日志基础上增加 Qt 键鼠/滚轮事件。

```text
python main.py --log --log-events --log-interaction
```

同时观察 Qt 事件进入情况和画布内部处理链，适合排查“事件收到了但功能没有执行”。

```text
python main.py --log --log-events --log-interaction --log-mouse-move
```

进一步记录合并后的鼠标移动轨迹，适合分析拖动过程中的事件目标、按钮状态和移动范围。

## 7. 启动时快捷键快照

日志创建后、主窗口创建前，会读取当前配置中的完整快捷键配置，并写入：

```text
category: config
name: startup_shortcuts
```

该快照包含本次程序启动时全部快捷键字段和值。因此后续即使用户在程序运行期间修改快捷键，分析日志时仍能知道本次运行开始时使用的快捷键配置。

## 8. 日志记录原则

日志功能不能改变正常业务逻辑。日志写入失败时不得阻止主程序运行。

键鼠事件通过 `QApplication` 的全局事件过滤器记录，因此可以观察事件实际到达的 Qt 控件，而不仅仅记录业务层已经处理的事件。

画布鼠标事件还通过 viewport 的事件过滤机制进入画布内部交互处理，因此 `events` 和 `interaction` 可以分别用于定位“事件是否到达”和“事件到达后是否正确处理”。

鼠标移动属于高频数据，默认关闭；即使开启，也使用状态分段而不是逐事件记录，以控制日志体积。

## 9. 日志分析的一般顺序

遇到 GUI 问题时，优先按照以下层次分析：

```text
1. logger_started / application_start
   ↓
确认程序启动、命令行参数和日志分类

2. events
   ↓
确认 Qt 是否实际收到对应键盘/鼠标/滚轮事件

3. interaction
   ↓
确认画布内部是否进入对应处理链

4. state / api
   ↓
确认内部状态或关键程序操作是否发生预期变化

5. canvas_painted 等状态日志
   ↓
确认最终视觉刷新是否发生
```

这样可以将问题逐层缩小，而不是一开始就从大量代码中寻找原因。

## 10. 滚轮问题排查方法

针对 `Alt + 鼠标滚轮` 无响应的问题，建议使用：

```text
python main.py --log --log-events --log-interaction
```

然后分别执行：

1. 普通滚轮一次；
2. 按住 `Alt` 滚轮一次；
3. 再执行“原始尺寸”；
4. 再执行“适应窗口”。

重点检查日志中的 `wheel`、画布滚轮处理、缩放相关状态和 `zoom` 变化。

如果还需要确认鼠标在事件发生前后的具体位置，再增加 `--log-mouse-move`。

判断逻辑：

```text
没有 wheel 事件
    ↓
Qt 没有收到滚轮事件，继续排查事件传播/系统层

有 wheel，但没有 Alt
    ↓
继续排查修饰键状态

有 Alt + wheel，但没有 zoom
    ↓
继续排查滚轮增量或缩放条件

有 zoom / set_zoom
    ↓
继续排查缩放后的绘制、滚动范围和视觉结果
```
